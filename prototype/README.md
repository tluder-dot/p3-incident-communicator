# prototype/ — Incident Messenger v1 (Assignment 4)

The smallest thing that can pass or fail our success criterion (`03_product_brief.md` §7). Built from `spec.md`, four steps, one commit per step. Fake data only.

```
ticket ─▶ [1 router + attach] ─▶ [2 routing rule] ─▶ [3 drafter] ─▶ [4 guardrail checker] ─▶ ⊘ IC approves (first message) ─▶ sent
```

| Step | File | Rung | What it decides |
|---|---|---|---|
| 1 | `router.py` | 2 · classical ML (TF-IDF words + characters → logistic regression) | the category: status · impact · cause_credit · unrelated |
| 1 | `attach.py` | 1 · rules (time window · account region · component words) | which open incident, with a confidence; two within 0.10 → never merged |
| 2 | `route_rule.py` | 1 · rules | auto-reply · auto-acknowledge rule · human queue · top of the queue |
| 3 | `draft.py` | 1 · template for customer replies · 3 · LLM (or mock) for the IC's status-update draft | the text — approved facts only |
| 4 | `policy.py` | 1 · rules | pass or block: no cause, ETA, data-loss claim, internal number, other customer, secret |

Around the four steps: `pipeline.py` (runs them in order), `switch.py` (the override switch ⏻: ON · SUGGEST_ONLY · OFF), `evals.py` (the eval-set run), `grading.py` (sheets for the two human graders, agreement rates), `app.py` (the IC console), `rollback_drill.py` (tests the switch and logs the test).

Data (`data/`): `incidents.json` — the four synthetic incidents and the facts the IC approved, version by version (our "knowledge base") · `accounts.csv` — ten invented customer accounts · `tickets_synthetic.csv` — 240 synthetic tickets that train the router (generated by `make_tickets.py`, never eval data) · `demo_inputs.csv` — the ten demo inputs of the console, never eval data.

## Run it

```bash
python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r prototype/requirements.txt
python prototype/evals.py evals/eval_set_v0.csv           # the number against the criterion (spec.md done_criteria)
streamlit run prototype/app.py                            # the IC console + the eval page
python prototype/rollback_drill.py "Your Name" "Your role" # tests the switch, logs it in evals/rollback_tests.csv
```

No API key: the status-update drafter uses the mock drafter (same contract, same inputs). With `ANTHROPIC_API_KEY` in `.env` (never in Git) it calls the model, restricted to the alert line and the incident channel; customer replies never use a model.
